# L0 training-record integration

Phase L0d3, 2026-10-06; follows the typed planner and development generator. CPU implementation only.

- Hypothesis: the parent's existing decision trainer can consume the language generator's typed slot supervision without changing model architecture or passing gold answers as current-slot inputs.
- Deliverable: a small exporter under language_growth/ to Track D's existing `{id, request, labels}` record format, keeping training and iterative development-validation domains explicit. It copies each existing request rather than reconstructing its state. Previous gold slot choices remain explicitly teacher-forced training context; this is not free-running evaluation.
- Exit proof: synthetic CPU tests reject split misuse, malformed/misaligned targets and duplicate identities; changing current labels does not change serialized model input. A CPU integration check passes exported records to Track D's actual `items_from_records` with a byte encoder and independently checks option-index labels. Exact committed dependencies and generated data hashes accompany the receipt.
- Decision unlocked: use the shared trainer for bounded supervised language adaptation after the frozen-parent probe, hardware qualification and separately acknowledged spend gate. Export success does not establish learning, retention, task capability or causal interpretation.

No Index or held-out data, weights, GPU, paid execution or new training framework is needed. Full L0–L4 goal gates remain unchanged.

## Reproducible training cohort builder

`python -m language_growth.training_cohort --output <empty-or-new-directory> --seed 271828 --count 5000 --choice-format mixed --split development_train` generated the initial synthetic training cohort. The full cohort contains 5,000 `development_train` tasks and 13,332 exported choice slots; its raw records remain in `C:/Users/apumu/research/CHLabs/ssdm-data/l0-training-cohort-20261006-seed271828-5k/`. A fresh-context reviewer independently regenerated and matched all exported JSONL rows byte-for-byte. The committed receipt/manifest are in `receipts/2026-10-06-L-l0-training-cohort/`. This is an initial training cohort, not an audit set or learned result. The CLI has no external data input and refuses every split except `development_train` before generation. It uses the existing development generator and training-record exporter; production and augmented choices are balanced under `mixed`. Repair is disabled for this supervision cohort.

The builder refuses a nonempty output directory or a file at the output path. Before writing, it verifies the exact permitted evidence and earlier gold prefix with the exporter, checks the complete bridge request for additional supervision fields, and parses every exported slot through `train.data.items_from_records` with `heads.layout.ByteEncoder` and a synthetic-only SplitGuard. It independently checks Item identities and the adapter's option-index labels. No model is constructed or loaded.

Outputs are `training_records.jsonl`, `development_manifest.json`, and `receipt.json`, encoded as sorted compact ASCII JSON with LF endings. The receipt binds the Git source SHA and dependency-file hashes, source cleanliness, command and working directory, seed/count/split, exact task and record aggregate and per-row hashes, task/slot/kind/choice-format counts, CPU/Python/platform information, zero paid cost, and verification scope. Each task retains one shared record identity across its slots; the D adapter appends question IDs for unique Item identities. Earlier gold slots are teacher-forced context; successful export establishes no learned or free-running result.

Focused CPU proof: `py -3.12 -m pytest -q language_growth/tests/test_training_cohort.py language_growth/tests/test_training_records.py language_growth/tests/test_development_data.py` — **24 passed** on 2026-10-06. Builder tests use only temporary 1–6 task training cohorts and cover deterministic bytes/hashes, the actual shared D adapter, changed current labels/private programs leaving requests unchanged, injected supervision rejection, split refusal before generation, and overwrite refusal. No persistent cohort or training run was created.

## Bounded CPU optimizer-to-planner check

Before a paid adaptation, test the same exported slots through Track D's existing Trainer and DecisionModelBackend using its tiny randomly initialized recurrent test backbone. One optimizer step, one synthetic development task and one separate synthetic validation task, two CPU threads, no downloaded checkpoint and no CUDA. Exit proof: finite loss, changed trainable parameters, and real head decisions reaching the semantic planner without a transport failure. This unlocks an executable adaptation path, not a learned L0 gate or a claim about a qualified Track D checkpoint. Keep all decisions and failures in the test output; do not tune this tiny model for a score.

Extend the same bounded check through Trainer.save/load: rebuild the identical tiny frozen base, load the trained head/adapters with strict config and lineage checks, require exact full state equality, then run the restored model through the planner. Require both head and LoRA updates while frozen parameters stay unchanged. This tests deployment continuity; it does not qualify a large parent checkpoint.
