# Plain-read paired development phase

## Hypothesis and deliverable

The pinned parent can select the requested registered Fact directly and discover
the corresponding checked ReadFact/Assert program from identical initial
audience evidence. Add a minimal plain-read direct view and paired runner using
the existing paired-comparison capture and planner session validation. Candidate
construction includes every audience-permitted registered Fact with neutral IDs;
it never reads the reference program or prunes against task labels.

## Exit proof and decision

CPU scripted tests must show full candidate retention, label-independent request
construction, identical initial state/model/revision/config pins, independent
post-call target scoring, wrong supported selections preserved, and accounting
for rejected or failed provider calls. Raw requests/responses and planner calls
remain available in the report. Plain-read cases exclude Explain, Ask and Sum.
The proof unlocks independent review and integration of this development probe;
it establishes no learned capability or level gate.

The existing strong unrestricted comparator and full parent retention remain
required for future qualification. This phase does not run models, load Torch,
use GPUs, download weights, spend funds, or touch Index/untouched evaluation
items. No push occurs before the coordinator reviews the implementation.
