# L0 bounded task-relevance release gate

## Hypothesis

Kernel-valid evidence does not establish that the selected program answers the user's question. A bounded exact-grammar task contract can refuse supported-but-wrong-entity, wrong-field, wrong-order and wrong-act programs before public text release, without rewriting the model's proposal.

## Deliverable

Add a fail-closed parser for the fixed L0 development read/explain/compare phrasings, resolve exact entity mentions only against the audience-permitted snapshot, and compare the resulting operation/fact bindings against the already kernel-accepted typed program. Unsupported wording, any duplicate visible entity name (even where only one duplicate has the requested field), ambiguous parse, or mismatched program is unavailable. The bounded implementation uses exact case-sensitive template text and caps snapshot records/entities/fields to bound work. Its contract hashes the task-visible state plus the complete active snapshot, policy, registry, and semantic host fields, then rechecks them after inference. The relevance gate does not choose/rewrite operands, compute values/relations, or render text.

## Exit proof

- Every supported fixed task form maps to the expected task kind, ordered entities and field.
- Supported correct reads/explanations/comparisons pass; a kernel-valid wrong fact, field, entity, operand order or speech act fails closed.
- Explicit negation, unsupported natural wording, duplicate entity names, private/hidden records and injected task text fail closed before provider use or release. Kernel-valid wrong-entity/field/order/speech-act programs and multiple textual parses are refused.
- Existing planner/kernel/renderer and public-output tests pass; a receipt records the exact CPU command and source hashes. No Index/held-out, model/GPU or paid work.

## Decision unlocked

Whether the bounded public projection can claim task relevance for these enumerated L0 query forms. It does not prove a model understood the task or generalize the claim to unsupported natural language; unrestricted useful-answer capability still requires separate evaluation against a strong comparator.
