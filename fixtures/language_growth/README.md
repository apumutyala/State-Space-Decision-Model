# Language-growth pilot fixtures

These 24 synthetic cases make the proposed [v0.1 boundary](../../interfaces/DECISION_LANGUAGE_V0.md) reviewable. They are development fixtures, not empirical model results, independently authored evaluation labels, held-out items, or a Decision Index benchmark. The nine catalog records are trusted only within their declared toy worlds and make no real-world product claims.

`manifest.json` lists stable case, world, and decision-question IDs. `catalog.json` contains four snapshot worlds, policies, and a proposed operation registry. Each case records host inputs, a proposed program, authored expectations, and a same-question `decision_only` choice task. Expected task labels and targets are evaluator annotations only. They must never enter a model request. Cases sharing a world must stay together in any future split.

The decision options use opaque IDs such as `LG01-o01`. `option_key_map_evaluator_only` preserves each semantic key for audit, and `relabel_control` gives a deterministic one-position ID rotation with its own target ID. A retention run must present the identical question, permitted evidence, policy, option descriptions, and option order in both arms, changing only the IDs according to `id_map`; it must score each arm against its matching evaluator-only target. Option descriptions do not include target-only values. This control exposes ID-order sensitivity; it does not by itself remove all model or task biases. The Track L bridge's `serialization_ref` must pin the actual decision-only to `decide()` request before observed retention scores are claimed.

Expectations have distinct layers. `provider_precondition` is checked by Track L before any Track D `decide()` call. In LG15, `provider.state_binding.audience != host.audience` fails that gate, so the original request contributes one request but zero provider-valid and answerable requests; no D or kernel result is expected. The decision-only target applies only to a separately rebuilt public-state arm. `kernel_status` concerns evidence-relative support and permission. LG14 and LG17 are expected to be accepted but task-wrong because the host supplies no formal relevance obligation. `task_outcome` and `useful_complete_answer` are authored task annotations; an appropriate ASK is not a complete substantive answer. Report asks, avoidable asks, provider exclusions, and denominators separately in later runs.

`host.limits.max_program_nodes` is a program limit. `host.limits.max_proposal_calls` and `max_repair_calls` are Track L limits across provider requests and repair requests, respectively; neither is forwarded as a Track D per-request limit. The current typed-choice planner budgets four requests for a comparison (operation, left input, right input, relation), so LG18 declares a budget of eight for one repair and LG19 declares four to block a repair after the initial comparison. The scripted evaluator instead consumes authored complete ASTs: two attempts in LG18 and one in LG19. These attempt counts are separate from actual D requests, which only a planner trace can measure. LG19 does not claim that the stateless D adapter returned `exhausted`; latency and cost are unmeasured.

Programs use `ssdm.semantic_program.v0.1`: `ReadFact` returns a subject-bound Fact, `Assert.proposition` references its node, and `Compare` consumes explicit `{node, project: "object"}` projections. Numeric values are exact integers or decimal strings. Comparison requires equal units and time scopes; no currency conversion, implicit temporal conversion, generic negation, or new arithmetic is licensed. `Conjoin.speech_acts` and `Ask.obligation_ref/references` follow the canonical contract. LG05 and LG20 test unregistered operation rejection. LG06 tests rejection of an extra `Conjoin` field. None proves natural-language negation or causal reasoning; the Cedar decision arm exercises the open-world question separately. LG13 tests a source-role injection through renderer and decision behavior; its kernel path does not read the malicious `display_name`. LG22's dangling record reference is admitted by a single-case validator allowlist, while LG23 tests a known policy-denied private dependency and LG24 exceeds the node limit.

Run packaging checks from the repository root:

```text
python fixtures/language_growth/validate.py
python -I -m unittest discover -s fixtures/language_growth -p test_fixture_pack.py -v
```

The standard-library validator checks JSON shape, manifest coverage, exact numeric representation, declared references, neutral IDs, reason-code coverage, and that the canonical contract declares the manifest's semantic-program schema. It intentionally allows LG22's one declared dangling proposal reference. It does not execute programs, prove expected truth, enforce audience isolation, test a renderer, or certify model behavior. A future runtime evaluator may produce observed checker/provider/renderer results; `language_growth.evaluate` is not supplied by this fixture pack.

LG22 and LG23 deliberately share `unknown_reference`: repair feedback must not distinguish missing and hidden records. A forbidden entry inside an offered snapshot is tested separately by the kernel isolation tests; this pack does not claim that rejection-code coverage. Scripted repair uses `repair.max_scripted_attempts`, independent of the declared planner request budgets.
